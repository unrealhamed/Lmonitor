# سیستم هوشمند هدف‌گذاری مالی (Smart Financial Goals)

نمونه‌ی اولیه‌ی قابل‌تعامل با HTML/CSS/JS خالص، بدون build و بدون وابستگی.
صفحه‌ی خانه دقیقاً از روی طرح مرجع (پالت آبی اقیانوسی + سبز نعنایی) ساخته شده و همه‌ی کارت‌ها به سبک **Liquid Glass**
(شیشه‌ی مات با blur، لبه‌ی گرادیانی روشن و درخشش نرم) طراحی شده‌اند.

```
finance-app/
├── index.html          پوسته‌ی اپ (RTL، فونت وزیرمتن)
├── css/styles.css      سیستم طراحی: توکن‌های رنگ، شیشه‌ی روشن/تیره، کامپوننت‌ها
├── js/engine.js        موتور مالی (توابع خالص، بدون DOM — در مرورگر و Node کار می‌کند)
├── js/data.js          داده‌ی نمونه (اعداد صفحه‌ی خانه = اعداد طرح)
├── js/app.js           لایه‌ی رابط کاربری، مسیریابی، شیت‌ها، انیمیشن جشن
└── tests/engine.test.js تست‌های واحد موتور:  node finance-app/tests/engine.test.js
```

**اجرا:** فایل `index.html` را مستقیم در مرورگر باز کنید. داده‌ها در `localStorage` ذخیره می‌شوند؛
از منوی «بیشتر ← بازنشانی داده‌های نمونه» می‌توانید به حالت اول برگردید.
لینک مستقیم صفحه‌ها: `#goals`، `#goal=g1`، `#assets`، `#achievements`.

## ۲. صفحات

1. **خانه** — بازسازی طرح مرجع: ارزش خالص (با نمودار درخشان)، اکشن‌های سریع، درآمد/هزینه، روند ۶ ماهه، توزیع دارایی، آخرین تراکنش. دکمه‌ی «هدف‌گذاری» وارد سیستم اهداف می‌شود.
2. **داشبورد اهداف** — نوار سطح/XP/استریک، **مهم‌ترین هدف در بالا** با Progress Ring، کارت ظرفیت ماهانه (سهم هر هدف + صندوق اضطراری)، هشدار وقتی مجموع نیاز از ظرفیت بیشتر است، فهرست سایر اهداف با جابه‌جایی اولویت (▲▼)، اهداف تکمیل‌شده.
3. **جزئیات هدف** — رینگ پیشرفت، هشدار عقب‌افتادن/جلوتر بودن، پیشنهاد تمدید مهلت یا افزایش اولویت (فقط با تأیید کاربر)، تحلیل هوشمند (۵ سؤال اصلی)، سه سناریو با مقایسه‌ی زمان/مبلغ/فشار، What‑If، برنامه‌ی روزانه/هفتگی/ماهانه، رودمپ گرافیکی، منابع در دسترس (سرمایه‌گذاری با کسر ریسک)، تاریخچه‌ی تغییرات رودمپ.
4. **ساخت/ویرایش هدف** (Bottom Sheet) — نام، تصویر (ایموجی یا آپلود)، قیمت، مبلغ کنار گذاشته، تاریخ (شمسی)، اولویت، رشد قیمت؛ با **پیش‌نمایش زنده** از موتور.
5. **واریز** — انتخاب هدف، مبالغ پیشنهادی (هفتگی، ماهانه، جبران، تا نقطه عطف بعدی)، نمایش مازاد ماه برای پس‌انداز مسئولانه.
6. **وضعیت مالی** (دارایی‌ها) — ویرایش درآمد، هزینه‌ها، نقد، سرمایه‌گذاری‌ها، بدهی‌ها + دکمه‌های «شبیه‌سازی رویداد» (افزایش حقوق، هزینه جدید، سود/زیان سرمایه‌گذاری) برای تست رودمپ پویا.
7. **گزارش و دستاوردها** — سطح، استریک، نشان‌ها (قفل/باز)، اهداف تکمیل‌شده، تاریخچه.

## ۴. منطق محاسباتی

همه‌ی مبالغ به تومان؛ زمان به ماه کامل؛ نرخ‌ها سالانه و به ماهانه تبدیل می‌شوند: `r_m = (1+r)^(1/12) − 1`.

**توان پس‌انداز**
```
خروجی ماهانه  = هزینه ثابت + هزینه متغیر + اقساط
مازاد         = درآمد − خروجی ماهانه
صندوق اضطراری = خروجی ماهانه × تعداد ماه (پیش‌فرض ۳)
نقد آزاد       = max(0, نقد − پس‌انداز اهداف − صندوق اضطراری)
بازسازی اضطراری = اگر کسری دارد: min(کسری/۶ ، ۳۰٪ مازاد)
ظرفیت پایدار   = مازاد × (۱ − ۲۰٪ بافر ایمنی) − بازسازی اضطراری
```

**سرمایه‌گذاری ≠ نقد:** ارزش قابل‌استفاده = ارزش × ضریب نقدشوندگی × (۱ − کسر نوسان).
مثلاً سهام: ۸۵٪ × ۷۰٪ ≈ ۶۰٪ ارزش. این مبلغ هرگز خودکار وارد محاسبه نمی‌شود؛ فقط در What‑If و با هشدار.

| نوع | نقدشوندگی | کسر نوسان |
|---|---|---|
| سپرده | ۹۵٪ | ۰ |
| صندوق | ۹۰٪ | ۲۰٪ |
| سهام | ۸۵٪ | ۳۰٪ |
| طلا و ارز | ۹۰٪ | ۱۵٪ |
| رمزارز | ۸۵٪ | ۵۰٪ |
| ملک | ۲۰٪ | ۱۰٪ |

**قیمت هدف با تورم:** `T(t) = قیمت × (1+g_m)^(ماه‌های گذشته از ثبت قیمت + t)`

**مبلغ ماهانه‌ی لازم برای مهلت n ماه** (فرمول اقساط با سود سپرده r):
```
PMT = (T(n) − موجودی × (1+r)^n) / (((1+r)^n − 1) / r)        (برای r = 0 مخرج = n)
```

**تخصیص بین اهداف:** ۱۵٪ ظرفیت بر اساس وزن (اولویت زیاد=۳، متوسط=۲، کم=۱ + امتیاز رتبه) بین همه پخش می‌شود تا هیچ هدفی کاملاً متوقف نشود؛ ۸۵٪ باقی به ترتیب اولویت تا سقف نیاز هر هدف؛ مازاد = «ظرفیت آزاد».

**زمان رسیدن:** شبیه‌سازی ماه‌به‌ماه کل سبد تا ۶۰۰ ماه. وقتی هدفی تمام شود، سهمش خودکار به اهداف بعدی می‌رسد (و این در تاریخ‌ها لحاظ می‌شود). اگر رشد قیمت از سرعت پس‌انداز جلو بزند، نتیجه «نامشخص/دست‌نیافتنی» است.

**واقع‌بینی هدف**

| وضعیت | شرط |
|---|---|
| راحت | سهم تخصیصی ≥ نیاز و نیاز ≤ ۲۵٪ مازاد |
| واقع‌بینانه | سهم تخصیصی ≥ نیاز |
| چالشی | نیاز ≤ ظرفیت پایدار (اگر اهداف دیگر کندتر شوند ممکن است) |
| پرفشار | نیاز ≤ کل مازاد (بدون بافر ایمنی) |
| غیرواقع‌بینانه | نیاز > کل مازاد |
| نیاز به بازنگری | مازاد ≤ ۰ |

**سناریوها:** محافظه‌کارانه = ۷۵٪ سهم، متعادل = سهم فعلی، سریع = ۱۳۵٪ سهم ولی **حداکثر تا ۹۵٪ مازاد واقعی** (فقط از بافر استفاده می‌کند). فشار مالی = سهم از درآمد (کم ≤ ۱۵٪، متوسط ≤ ۳۰٪، زیاد).

**رودمپ:** نقاط عطف ۱۰/۲۵/۵۰/۷۵/۱۰۰٪ از قیمت پیش‌بینی‌شده در روز رسیدن. تاریخ هر نقطه از سری شبیه‌سازی؛ وضعیت: انجام‌شده / در جریان / در انتظار. آهنگ پس‌انداز: روزانه = ماهانه×۱۲/۳۶۵، هفتگی = ماهانه×۱۲/۵۲.

**عقب‌ماندن از برنامه:** انتظار = موجودی پایه + ماهانه‌ی توافق‌شده × ماه‌های گذشته. اگر فاصله بیش از نصف قسط ماهانه باشد هشدار می‌دهد و دو راه پیشنهاد می‌کند: واریز جبرانی یا به‌روزرسانی برنامه از امروز.

**رودمپ پویا:** پس از هر تغییر در پروفایل، اولویت یا هدف، برنامه‌ی قبل و بعد مقایسه می‌شود (`diffPlans`) و برای هر هدف «چه تغییر کرد» (زمان، سهم ماهانه، وضعیت) و «چرا» (درآمد، هزینه، سود/زیان سرمایه، …) ثبت و نمایش داده می‌شود. **قیمت، مهلت و اولویت هدف هرگز خودکار تغییر نمی‌کنند**؛ تمدید مهلت فقط با دکمه و تأیید کاربر.

## ۵. گیمیفیکیشن مسئولانه

* **XP برای استمرار، نه مبلغ:** اولین واریز هر هفته ۲۰ XP + پاداش استریک (حداکثر ۵۰). واریز دوم همان هفته XP ندارد، پس واریز بزرگ‌تر امتیاز بیشتری نمی‌دهد.
* نقاط عطف: ۵۰ / ۱۰۰ / ۲۰۰ / ۳۰۰ / ۵۰۰ XP؛ ساخت هدف ۳۰ XP.
* سطوح: تازه‌کار ← پس‌اندازگر ← برنامه‌ریز ← هدف‌گیر ← استراتژیست ← …
* استریک هفتگی (هفته از شنبه).
* نشان‌ها: اولین قدم، شروع پس‌انداز، یک‌چهارم راه، نیمه راه، رسیدم!، ۴ و ۱۲ هفته پیوسته، **پس‌انداز مسئولانه**، چندهدفه، برنامه‌ریز، سطح ۵.
* **محافظ:** اگر واریزهای ماه از مازاد واقعی بیشتر شود، هشدار داده می‌شود و نشان «پس‌انداز مسئولانه» داده نمی‌شود.
* انیمیشن کانفتی و کارت جشن هنگام رسیدن به نقطه عطف، سطح یا نشان جدید (با احترام به `prefers-reduced-motion`).

Game {

## ۷. ارتباط بخش‌ها و توسعه‌ی آینده

* موتور (`engine.js`) هیچ وابستگی به DOM ندارد؛ می‌توان آن را بدون تغییر به بک‌اند (Node) یا اپ موبایل (React Native) برد.
* `localStorage` را می‌توان با یک API جایگزین کرد: کافی است `load/save` در `app.js` عوض شوند.
* اتصال تراکنش‌های بانکی واقعی: تراکنش‌ها `monthlyIncome/expenses` را به‌روز می‌کنند ← `recordReplan` همان توضیح تغییرات را تولید می‌کند.
* ضرایب نقدشوندگی/نوسان، بافر ایمنی و سهم رزرو در بالای `engine.js` به‌صورت ثابت تعریف شده‌اند و قابل تنظیم یا شخصی‌سازی‌اند.

## ۸. بخش سرمایه‌گذاری (`js/invest.js`)

نُه صفحه در یک نما با تب: داشبورد، ریسک‌سنجی، سبد من، دسته‌ها، تحلیل بازار، سیگنال‌ها، مقایسه، بازتنظیم، تاریخچه.

* **سبد از روی معاملات:** میانگین موزون بهای خرید، سود/زیان تحقق‌یافته و تحقق‌نیافته. ارزش سبد = قیمت فروش منهای کارمزد خروج، یعنی پولی که واقعاً دستت می‌رسد. دارایی خارج از اپ هم قابل ثبت است.
* **ریسک = کمترِ (تحمل روانی، توان مالی):** توان مالی از صندوق اضطراری، نرخ پس‌انداز، بار بدهی و افق نزدیک‌ترین هدف ساخته می‌شود؛ بنابراین سبد فقط با روحیه‌ی ریسک‌پذیری ساخته نمی‌شود. تا پرسشنامه کامل نشود، هیچ پیشنهاد ترکیبی صادر نمی‌شود.
* **بازار ایران:** ارزش ذاتی طلای ۱۸ = اونس × دلار × ۰٫۷۵ ÷ ۳۱٫۱۰۳۵؛ ارزش ذاتی سکه = اونس × دلار × ۸٫۱۳۳ × ۰٫۹ ÷ ۳۱٫۱۰۳۵؛ برای نقره و مس هم مشابه. حباب = (قیمت بازار − ارزش ذاتی) ÷ ارزش ذاتی. اختلاف خرید/فروش، کارمزد، نرخ بهره‌ی واقعی و تورم هم محاسبه می‌شوند.
* **سیگنال‌ها:** هر سیگنال دلیل، منبع، زمان به‌روزرسانی و سطح اطمینان دارد. اگر داده نمونه یا کهنه باشد، سطح اطمینان کم می‌شود. هیچ سیگنالی پیش‌بینی قطعی نیست.
* **بازتنظیم:** هر کلاس دارایی که بیش از آستانه (۳/۵/۱۰٪) از تخصیص هدف فاصله بگیرد، فهرست می‌شود؛ مبلغ جابه‌جایی و هزینه‌ی تخمینی آن (کارمزد + اختلاف قیمت) هم نشان داده می‌شود.
* **داده‌ها:** `MARKET` فعلاً یک داده‌ی **نمونه** است و برچسب «نمونه» دارد. برای اتصال به داده‌ی واقعی، `MarketProvider.fetch()` را با فید ارز/طلای داخلی و فید جهانی فلزات جایگزین کنید؛ رابط کاربری فقط به همین ساختار داده وابسته است.

مدل داده: `invest = { txs: [{ id, asset, side, qty, price, fee, date, external }], answers: [0..3 × 5], threshold }`.

## ۹. واکنش‌گرا

* **آیفون:** نوار وضعیت ساختگی پنهان می‌شود، فاصله‌ها با safe-area تنظیم می‌شوند، فونت ورودی‌ها ۱۶px است تا صفحه زوم نشود، و برنامه به‌صورت وب‌اپ تمام‌صفحه قابل نصب است.
* **دسکتاپ (۱۰۲۴px به بالا):** منوی کناری راست، محتوای دوستونه، شیت‌ها به‌شکل پنجره‌ی وسط صفحه، و رودمپ سه‌بعدی بزرگ‌تر.
